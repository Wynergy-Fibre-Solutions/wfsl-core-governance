# WFSL Governance Change Policy

## Purpose
Define how governance artefacts may change after
a sealed WFSL release.

## Change Classes
- Editorial clarification (non-substantive)
- Superseding release (substantive)
- Retirement (historical reference only)

## Rules
- Sealed artefacts are immutable
- Editorial changes require a new commit but no new seal
- Substantive changes require a new release and signed tag

## Prohibitions
- No retroactive edits to sealed releases
- No silent changes to authority or scope
- No removal of historical artefacts

## Traceability
- All changes recorded in Git history
- Supersession links must reference prior seals

## Authority
WFSL Governance Authority

## State
Active.
