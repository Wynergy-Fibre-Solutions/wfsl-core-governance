# WFSL Supersession Policy

## Purpose
Define how future WFSL releases supersede prior sealed releases
without invalidating historical authority.

## Principles
- Supersession is additive, not destructive
- Prior seals remain valid for their scope
- New authority is declared explicitly

## Mechanics
- Each new release references the prior seal tag
- Superseding tags are unique and signed
- No history rewriting is permitted

## Compatibility
- Verifiers must accept historical seals
- Licence scopes may differ per release

## Audit
- Supersession chain is traceable via tags
- Git history provides full lineage

## State
Active.
